# CrowdWisdomTrading — Macro-Event Strategy-Selection Pipeline

An end-to-end, reproducible ML pipeline that **predicts which trading-strategy
parameter permutations will perform best in a future period**, using historical
trade logs joined with scraped macroeconomic event data, validated strictly
**out-of-sample** with walk-forward testing (purge + embargo). Built for the
CrowdWisdomTrading Quantitative Data Scientist intern assessment.

> **Design priorities (in order):** correctness → no look-ahead bias →
> reproducibility → clean code. *Not* model complexity.

---

## What it does (8 stages, one command)

1. **Macro event ingestion** — Apify economic-calendar actor (discovered at
   runtime from the Apify Store, id recorded) scrapes the last 180 days of
   high-impact US events (CPI, FOMC, NFP, unemployment, jobless claims);
   timestamps normalised to UTC with a DST-aware ET column. Tavily (and
   optionally Exa) pulls recent Fed/inflation/jobs/rates news with sentiment.
   All raw responses are cached to `data/raw/` so re-runs don't burn credits.
2. **Database layer (SQLite)** — `trades`, `macro_events`, `news`, `features`,
   `predictions`, `backtest_results` (+ `run_metrics`). Trades join to events by
   time (hours since last / until next event).
3. **Trade data** — no real logs were provided, so trades are generated by
   backtesting parameterised strategies (**documented stand-in**) on public
   yfinance data for a macro basket (SPY, QQQ, TLT, GLD).
4. **Feature engineering** — time, macro-surprise, sentiment, and strategy
   features, all built under a strict **as-of rule** (no look-ahead).
5. **Model + walk-forward validation** — LightGBM (sklearn HistGradientBoosting
   fallback) vs. naive baselines, expanding splits with purge/embargo.
6. **Evaluation** — Sharpe, Sortino, Max Drawdown, win rate, profit factor,
   number of trades vs. baselines → `reports/evaluation_report.md`.
7. **Visuals** — macro sentiment timeline, permutation×period heatmaps, equity
   & drawdown curves → `reports/figures/`.
8. **Macro outlook** — one-page `reports/macro_outlook.md` grounded in scraped
   events + news with sources.

### External Trade Logs Integration

The pipeline supports importing real trading logs in CSV format. If a `trades.csv` is provided in `data/raw/`, the `trades` stage will ingest it instead of generating simulated trades.

**Schema Requirements (`trades.csv`):**
| Column | Type | Description |
| :--- | :--- | :--- |
| `permutation_id` | string | Unique ID for the strategy configuration. |
| `family` | string | Strategy family name (e.g. 'breakout', 'mean_reversion'). |
| `symbol` | string | Ticker symbol. |
| `side` | string | 'LONG' or 'SHORT'. |
| `entry_time` | ISO8601 | Entry timestamp (UTC). |
| `exit_time` | ISO8601 | Exit timestamp (UTC). |
| `pnl` | float | Absolute PnL in USD. |
| `params_json` | string | JSON string of strategy parameters used for features. |

## No-look-ahead: how it's enforced

Every feature used to predict period *t* uses **only information available at
the start of period *t***:

- **Trades**: only trades *closed* strictly before *t* contribute to a
  permutation's rolling-performance features (lagged).
- **Macro values**: `surprise = actual − forecast` is usable only *after* the
  release; standardisation uses an **expanding z-score shifted to exclude the
  current observation** (past events only).
- **Event schedule**: "hours-to-next-event" and event-window flags *are* known
  in advance (the calendar is public), so they're allowed pre-release.
- **News**: rolling sentiment uses only articles *published* before *t*.
- **Walk-forward**: expanding train window, a **purge** of training rows whose
  trade/label window overlaps the test period, and an **embargo** gap.

This is covered by `tests/test_no_leakage.py` (corrupt-the-future test) and
`tests/test_walkforward.py`.

## Key assumptions & limitations

- **Stand-in trades.** No trading logs were provided; trades come from a simple
  MA-crossover + breakout grid on public data. A *permutation* = one unique
  parameter combination, evaluated on its aggregate basket performance.
- **180-day macro window (per the brief).** With weekly periods this yields only
  ~25 folds (~15 usable out-of-sample after warm-up + embargo) — a genuinely
  small sample. Reported honestly; the grade is on methodology, not on beating
  the baseline. The window is configurable in `config.yaml`.
- Keys are read only from `.env`; raw API responses are cached; all RNG seeds
  are fixed for reproducibility.
